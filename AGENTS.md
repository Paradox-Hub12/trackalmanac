# Instructions for AI assistants working on Track Almanac

Read this first, then `README.md` (how the site is built and what the automation does).
Track Almanac (https://trackalmanac.com) is an unofficial Formula 1 fan site, hosted on GitHub Pages
from this repository. Every push to `main` is live within about a minute.

## How you work here
You are a full maintainer of this site, with the same freedom as the owner's other assistant (Claude): you can change
anything (data, design, features, scripts, workflows). The owner doesn't review or merge anything by hand:
**push straight to `main`**, or, if you can only open a pull request, open it (not as a draft). The "Auto-merge"
workflow builds it, checks every page in a browser and **merges it automatically** when everything passes, then
deletes the branch. If a check fails, the pull request stays open and the owner is emailed: fix it on the same branch.
Never ask the owner to merge, pull or push.
**A task is only finished when the change is on GitHub** (pushed to `main`, or a pull request opened). Changes left in
your workspace never reach the site. End every task that changed files by pushing or opening the pull request
yourself, and say which one you did (commit or pull request link). Freedom comes with responsibility: everything you push is live within about two minutes, so
**test before you push** (see "Quality checks") and tell the owner briefly what you changed and why.
The owner's other assistant reviews the site from time to time, so keep commits small, well described and easy to check.

## House rules
- **Edit the master files, never the generated ones.** The masters are `src/` (data, design and app), `build.py`,
  `historylib.py`, `scripts/` and `.github/workflows/`. Everything else at the top level (`index.html`, page folders,
  `app.js`, `data.js`, `style.css`, `sitemap.xml`, `data/archive/`, `img/`) is generated by `python3 build.py`.
- **After any change:** `python3 build.py`, then `node --check app.js && node --check data.js`, run the quality
  checks, then commit the masters and the rebuilt files together. If you can't run commands, committing only the
  change in `src/` is fine: the "Rebuild site" workflow rebuilds and publishes the site within a couple of minutes
  (and fails, with an email to the owner, if `src/data.json` is broken).
- **Never** commit secrets, keys or tokens. The Firebase web config in `src/game.json` is public and fine.
  Never touch the GitHub secret `FIREBASE_SERVICE_ACCOUNT`.
- **No test branches left behind** (delete your branch once its pull request is merged). No test files in `main`.
- **Unofficial site:** no F1, team or driver logos, no copyrighted race photos. Neutral wording about real people.
- **Check facts with at least two sources** (Formula1.com, FIA documents, The Race, Motorsport.com, RacingNews365,
  Crash.net…). Early reports are often wrong (grids published before late penalties, results before post-race penalties).
- **The automation** (`scripts/update.py`, every 30 minutes Friday–Monday UTC) only *adds* missing data and never
  overwrites anything. So a correction you make stays, but a wrong value already in `src/data.json` is never fixed by it.
- **Edit `src/data.json` with Python, not by hand:**
  ```python
  import sys; sys.path.insert(0, "."); import build
  D = build.load_data()
  # ... change D ...
  build.save_data(D)
  ```

## Quality checks (before every push that changes how pages look or behave)
1. `python3 build.py --check` (builds into a temporary folder and reports) and `python3 build.py`.
2. `node --check app.js && node --check data.js`.
3. Browser check of every page: no JavaScript errors and nothing wider than the screen.
   ```
   npm i --no-save playwright@1.47.2 && npx playwright install chromium     # once per environment
   node scripts/site_check.mjs --quick         # every page at 390px and 1366px (a few minutes)
   node scripts/site_check.mjs                 # 5 widths (320-1366px), dark and light: after design changes
   node scripts/site_check.mjs / /races/2026/brazil/    # just the pages you touched
   ```
4. For anything that depends on time (countdowns, Predictor states, race-day modes), test by faking the clock
   (Playwright's `page.clock.install({time: ...})`) at each stage: before, during, after, and at the end of the season.
5. Look at it: take a screenshot of what you changed at phone and desktop width, in dark and light theme.
6. Data changes: re-read the changed rows, check totals add up (points, standings sorted, 20–22 cars per session).

## Data you will touch (all in `src/data.json`; round numbers are strings in SEASON, e.g. "20")
- `SEASON[round]["quali"]`: rows `[pos, car_no, surname, Q1, Q2, Q3, laps]`, e.g.
  `["1", 1, "Norris", "1:30.939", "1:29.207", "1:27.470", "24"]`.
  - A driver who reached a part but set no time gets `"No time"` there; parts not reached stay `""`.
  - Disqualified from qualifying: pos `"DQ"`, row moved to the end, the drivers behind move up one.
- `SEASON[round]["grid"]`: starting grid `[slot, car_no, surname]`, e.g. `[1, 1, "Norris"]`. Pit lane start: slot `"PL"`, at the end.
- `GRIDNOTES[round]`: plain-English explanation of every penalty and pit lane start (shown under "Why the grid differs").
- `SEASON[round]["race"]`: `[pos, car_no, surname, laps, time_or_gap, points, grid]`, where pos is `"NC"` if not classified.
- `SEASON[round]["tyres"]`: Pirelli compounds as a 3-digit string hard→soft, e.g. `"345"` = C3/C4/C5.
- `STANDINS[round][surname_lowercase_no_accents]`: `[full name, team, role]` for drivers not in the 2026 line-up,
  e.g. `"mini": ["Gabriele Mini", "Alpine", "FP1 driver"]`.
  - Use role `"FP1 driver"` for FP1-only outings: these drivers are NOT added to the Predictor's driver list.
  - Use `"stand-in"` for someone replacing a race driver.
  - The team must be spelled exactly as in `DRIVERS`.
- `RACES[i]["res"]["cls"]`: the short race write-up (4–5 sentences, facts only); `SEASON[round]["wxnote"]`: one-sentence weather note.
- `NEWS[round]`: short news lines from the owner, shown after the Predictor picks lock (see "Add a news line").
- `DRIVERS` `[name, nat, team, points]` and `CONSTRUCTORS` `[team, points]`: the standings, kept sorted by points.

## Race-weekend jobs (what the owner will ask for)

### "Add the FP1 stand-ins" (Friday)
1. Find who drove in FP1 instead of a race driver: drivers in `SEASON[round]["fp1"]` whose surname isn't in `DRIVERS`.
   The regular drivers missing from FP1 tell you whose car they used; confirm with a news article.
2. Add each to `STANDINS[round]` with role `"FP1 driver"`. A driver replacing someone for the whole weekend gets `"stand-in"`.

### "Update the grid" (after qualifying)
1. Check `SEASON[round]["quali"]` arrived with lap times. If the times are missing, fill them from the published classification.
2. Find every penalty: engine/gearbox grid drops, back-of-grid, pit lane starts, disqualifications.
   Use at least two sources published *after* qualifying.
3. Build the grid:
   - Drivers with more than 15 places of penalties, or a back-of-grid penalty, go to the back, in qualifying order.
   - Place-penalty drivers drop that many places from their qualifying slot.
   - Everyone else fills the gaps in qualifying order.
   - Disqualified-from-qualifying drivers go behind everyone, and pit lane starters go last with `"PL"`.
   - Cross-check against an FIA or major-outlet grid list.
4. Write `GRIDNOTES[round]`: one sentence per penalty, with places and reason.

### "A session time changed" (timetable change, rain delay, postponement)
Session times live in `SCHED[round]`: `[track time zone, [[session name, start in UTC, length in minutes], ...]]`, e.g.
`["America/Los_Angeles", [["Qualifying", "2026-11-21T04:00:00Z", 60], ...]]`. They drive the countdowns, the
"Session in progress" labels, the automation, and the Predictor's pick deadline (the start of "Qualifying").
- **Timetable changed in advance** (announced days before): the automation usually updates `SCHED` by itself when its
  two sources agree. If it hasn't, set the new UTC start by hand. Hand-entered times are never undone.
- **Delayed on the day** (rain, red flag, track repairs): **do nothing.** The results arrive when the session ends,
  and the Predictor deadline stays at the scheduled start, which is fair because nobody has seen the session yet.
- **Postponed to another day** (e.g. qualifying moved to Sunday morning): set the new UTC start in `SCHED` and
  rebuild. The Predictor's deadline follows it at the next run of the "Update results" workflow (every 30 minutes,
  Friday to Monday) or of "Firebase" (Actions → Run workflow).
  - Only move the Qualifying time **before the original deadline has passed** if possible. Moving it later after it
    passed reopens picks.
  - Never move it to a time after the session has actually started.
- **Session cancelled**: leave `SCHED` as it is and tell the owner. A cancelled qualifying (grid set from practice)
  needs a decision about the Predictor's pole points.

### "Add a news line" (race weekend, after the Predictor picks lock)
- `NEWS[round]` is a list of `[time in UTC, text]`, e.g.
  `"20": [["2026-11-08T18:06:00Z", "Norris leads in São Paulo after Kimi and Russell spin"]]`.
- Use the owner's text exactly as given (fix only obvious typos), with the current UTC time.
- Lines appear on the home page's next-race card from the start of qualifying until the race result is in.
  Newest first, at most 4. With no lines, the space stays empty. Never write news lines yourself unless asked.

### "Fix the result" (post-race penalties)
1. Apply time penalties to the race time / gap, re-sort the classified finishers, and reassign points (25-18-15-12-10-8-6-4-2-1).
2. Update `DRIVERS` and `CONSTRUCTORS` by the points difference only. A stand-in's points go to his team.

### "Weekly update" (Monday/Tuesday)
- Race write-up (`cls`) and weather note (`wxnote`). The measured weather is in `SEASON[round]["wxm"]`:
  one entry per day, `[air min, air max, track min, track max, % rain, max wind]`.
- Tyre compounds for upcoming races once Pirelli announces them.
- 2027 line-ups (`ENTRIES2027`): change only on an official team announcement, not reports.
- Next round's session times in `SCHED` against the official timetable.

## Handle with extra care (allowed, but test thoroughly and explain the change to the owner)
- `scripts/update.py` and `.github/workflows/`: the automatic results. A mistake can stop updates or write wrong
  data during a race weekend. Test with `python3 scripts/update.py --dry-run` and `--selftest <round>`.
- `firebase/firestore.rules`, `scripts/gamelib.py`, `scripts/score.py`: the Predictor's security and scoring. Rules
  changes are deployed automatically when pushed; a wrong rule can let players edit others' picks or lock everyone
  out. Points: P1 5, P2 3, P3 2, P4 1, P5 1, pole 3; no bonuses (the owner's decision).
- `titleWatch` / `titleDecided` in `src/app.html` and the champion logic in `historylib.py`: the title maths
  (tie-break on wins).
- `__/` (the Google sign-in helper pages, copied from Firebase by the "Firebase" workflow): don't edit by hand.
- Avoid big edits on race weekends (Friday–Sunday): if something breaks, revert your commit first, then fix.
