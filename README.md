# Track Almanac

Formula 1 results, standings & history — an unofficial fan site.

- **Live site:** https://trackalmanac.com
- **What's on it:** 2026 race calendar with next-race countdown, drivers' and constructors' standings, race-by-race results with circuit maps, and a past-seasons archive.
- **How it updates:** a GitHub Actions workflow adds new session results automatically during race weekends. Corrections and everything else are done by hand. GitHub Pages republishes after every push.

This repository is the master copy of the site. Start any change from the files here.

## Where things live

| File | What it is | Who changes it |
|---|---|---|

| `src/circuitmaps.json` | Track outline of every circuit layout for the Circuits page (F1DB circuit SVGs by Jules Roy, CC BY 4.0). Made by `scripts/history.py` | rarely |
| `historylib.py` | Works out the History page (career stats, champions, records, countries) at build time. Rounds newer than `src/history.json` are added from `src/data.json`, so it stays current after every race | — |
| `src/world.json` | World map outline for the 2027 route map (Natural Earth 1:110m via world-atlas, public domain, already projected) | design work |
| `build.py` | Builds the site from `src/` | — |
| `scripts/update.py` | Fetches new results into `src/data.json` | — |
| `.github/workflows/update.yml` | Runs `scripts/update.py` on a schedule | — |
| `src/game.json` | Predictor settings: season and the Firebase web config (public, safe to commit) | once, at setup |
| `scripts/gamelib.py`, `scripts/score.py` | Predictor scoring rules, and the scorer the workflow runs after `update.py` | — |
| `firebase/` | Firestore security rules (`firestore.rules`) and emulator config for the Predictor | when the game's data rules change |
| `src/vendor/firebase-game.js` | The Firebase JS SDK subset the game uses (Auth + Firestore lite), bundled by `scripts/vendor-firebase.sh` | only to update the SDK |

| `.automation/schedule-seen.json`, `.automation/check-failures.json` | What the sources last reported, and which check failures were already emailed | the update workflow (safe to delete: it starts fresh) |

Everything else at the top level (`index.html`, the page folders, `404.html`, `app.js`, `data.js`, `data/archive/<year>.json` (one file per archive season, loaded when its page opens), `data/world.json`, `data/history.json`, `data/circuitmaps.json`, `style.css`, `img/`, `sitemap.xml`) is generated by `build.py`. Don't edit it by hand; it's overwritten on every build. CNAME, .nojekyll, robots.txt, the icons, og-image.png and site.webmanifest are never touched by the build.

## Building the site

```
python3 build.py            # rebuild everything from src/
python3 build.py --check    # build into a temp folder and only report
```

Plain Python 3, no npm or packages. Run it after any change in `src/`, then commit everything.

The build makes one folder with an `index.html` for every page (`/`, `/championship/`, `/drivers/`, `/teams/`, `/calendar/`, `/races/2026/<slug>/`, `/archive/<year>/`, `/about/` …) plus `404.html`. Each page has its own title, description, canonical address, Open Graph tags, JSON-LD and its main content as plain HTML. Shared files (`style.css`, `app.js`, `data.js`, `img/`) are cached, and `sitemap.xml` gets a per-page `lastmod` (tracked in `.automation/build-state.json`).

## History page

`/history/` lists every World Championship driver since 1950 with career stats, champions by year (with the race where each title was won), all-time records and stats by country. `/history/circuits/` lists every circuit with its track map, lap record, most wins and every race held there, plus circuits in and out of every calendar from next season back to 1950, planned future circuits (`FUTURECIRC` in `src/data.json`, entered by hand with sources), a world map of every circuit, a lap-speed against corners chart, firsts and one-offs, and records. Signature corners and extra card facts are hand-written in `CIRCNOTES` in `src/data.json`, keyed by circuit id. Detailed track maps (turn numbers, corner names, start line, direction) are SVGs in the site style at `src/tracks/<circuit id>.svg`, drawn from F1DB outlines aligned to Wikimedia Commons diagrams; their colours come from style.css, so they follow the theme. The build copies them to `/img/` under a content hash and lists them in `TRACKIMG`; `src/tracks/notes.json` adds a layout note where the diagram is not the current layout. Circuit altitudes are in `CIRCELEV` (SRTM 90 m via Open Topo Data, one point per circuit) and coordinate fixes for circuits where F1DB's point is off the track are in `CIRCGEO`. `/history/constructors/` does the same for teams and engine makers: constructors' champions since 1958, every team and engine with a card (record, drivers' champions, engines or teams supplied, team history), team and engine records, and stats by country. `build.py` computes it from `src/history.json` plus the current season's results in `src/data.json`, so new races show up after every build without touching the history file.

To take in a newer F1DB release (for example to pick up corrections), download `f1db-json-splitted.zip` from https://github.com/f1db/f1db/releases, unzip it and run:

```
python3 scripts/history.py path/to/unzipped-folder path/to/f1db/src/assets/circuits
python3 build.py
```

Rounds newer than the F1DB release are added from the site's results using each driver's latest team. If a driver changes team after the newest F1DB round, refresh the F1DB file once it includes that race so the team totals stay exact.

## Automatic result updates

`.github/workflows/update.yml` runs every 30 minutes from Friday to Monday (UTC). Each run:

1. checks out the latest `main`
2. runs `python3 scripts/update.py`, which
   - finds every session in `SCHED` that has ended but has no data yet
   - fetches it from the free [Jolpica-F1](https://github.com/jolpica/jolpica-f1) API (race, sprint and qualifying results, standings, schedule) and the free [OpenF1](https://openf1.org) API (practice and sprint-qualifying classifications, lap-by-lap timing, race control, schedule) and [TracingInsights](https://github.com/TracingInsights) (per-lap tyre data from the official F1 timing feed, Apache-2.0)
   - writes it into `src/data.json` in the formats the site already uses: session tables, the race summary (`res`, without the `cls` note), the lap chart (`LAPS`), the sprint winner, the points in `DRIVERS` and `CONSTRUCTORS`, and the race extras below
   - runs `build.py`
3. commits the change as `Auto: R<round> <GP>: <session> results` and pushes it. If `main` changed in the meantime (for example a manual update), it redoes the update on top of the latest version first.

### Rules the script follows

- **Only adds missing data.** A session table, result, lap chart or note that already exists is never changed, so hand corrections are never undone. Standings only change by the points of a sprint or race the script adds itself.
- **Race extras** for each race (in `SEASON[round]`), shown on the race page under "How the race went", "Tyre strategy" and "Weekend":
  - `neutral`: safety car, virtual safety car and red flag periods from OpenF1 race control, e.g. `[["VSC", 8, 9], ["SC", 22, 27], ["RF", 3, 3]]` (type, first lap, last lap; `[]` = none). A VSC turned into a safety car ends the lap before; a red flag ends any running SC/VSC; stewards' notes are ignored. `["PIT", lap, lap]` marks the field being sent through the pit lane (e.g. Baku lap 36): the timing counts that as a stop, but nobody changes tyres.
  - `stints`: every driver's tyre stints, `{"<car number>": [["M", 1, 32, 0], ["H", 33, 62, 0]]}` (compound S/M/H/I/W, first lap, last lap, laps on the set when fitted). Built from TracingInsights' per-lap data (official F1 timing feed). The timing feed starts a new stint on every trip down the pit lane, so when the compound is the same and the tyre age just carries on (a drive-through penalty, waiting in the pit lane under a red flag, the field sent through the pit lane) it stays one stint. Every remaining tyre change must line up with an official pit stop lap from Jolpica-F1, or a red flag, or the stints aren't saved. OpenF1 is only used to name a compound the timing feed left unknown: its own stints were often a lap early, or scrambled in wet races and for pit-lane starters.
  - `wxm`: weather measured at the track, one entry per day of the weekend in the order of the race page's day cards: `[air min, air max, track min, track max (°C), % of readings with rain, max wind (m/s)]`, from TracingInsights' per-session `weather.json` (official timing feed). Zero readings (sensor gaps) are ignored. The hand-entered forecast (`wx`) stays and is shown underneath.
  
  Normal runs add these for races of the last 7 days. *Run workflow* with **backfill** ticked adds them for every finished race that's missing them. Like everything else they're only added when missing, so hand corrections stay.
- **Never writes** race notes (`cls`), grid notes, archive text, tyre compounds or weather.
- **No data yet → no change.** If a source hasn't published a session, it's skipped and the next run tries again.
- **Checks before saving.** These cover 20–22 cars per session; the same finishing order in Jolpica-F1 and OpenF1 for races and sprints; points that add up to the published standings; and standings sorted by points. A session that fails a check is not saved.
- **One email per problem.** The first time a check fails, the run fails, so GitHub emails the owner. If the same failure comes back on later runs (for example a slow source), it is only logged as a warning and the run passes, so you don't get an email every 30 minutes. Reported failures are kept in `.automation/check-failures.json`; once a failure is resolved it's removed from the file, and if it ever comes back it's reported again. A different failure always emails. Fix the data by hand (or wait for the sources to agree), and the next run carries on.
- **Schedule changes never undo hand-entered times.** For the current and next round, the session times each source reports are remembered in `.automation/schedule-seen.json`. `SCHED` is only changed when a source's time *changes* compared with what it reported on an earlier run, and both sources agree on the new time (more than 5 minutes away from `SCHED`). That change is committed as `Schedule: R<round> <session> moved to <time> UTC`. A difference that was already there is left alone. So if you enter a time by hand that the APIs haven't caught up with yet (like Singapore qualifying at 13:30 when both still said 13:00), it stays. If the sources disagree with each other, `SCHED` is left alone too. The run log lists every difference that was left alone.
- **Pit lane starts** come from the starting grid (`SEASON[round].grid`) when it has been entered by hand; the APIs only give numbered grid slots.
- The script respects rate limits (OpenF1 free tier: 30 requests a minute) and caches every response during a run. No login or paid plan is needed.

### Running it by hand

- **On GitHub:** Actions → *Update results* → *Run workflow*. Leave the box empty for a normal update. Enter a finished round number (e.g. `17`) to run the self-test instead: it removes that round's results from a copy of the data, rebuilds them from the APIs and compares them with the site. Nothing is saved, and the two state files in `.automation/` are neither read nor written.
- **On a computer:**
  ```
  python3 scripts/update.py --dry-run        # show what would be added, change nothing
  python3 scripts/update.py                  # add missing results and rebuild
  python3 scripts/update.py --selftest 17    # rebuild round 17 on a copy and compare
  python3 scripts/update.py --backfill       # also add missing race extras for every finished race
  ```

### Manual corrections

Edit `src/data.json`, run `python3 build.py`, commit and push. The workflow never overwrites what's there. For a new season or round, add the session times to `SCHED` and the round to `RACES`; the workflow fills in the rest as sessions finish.

## F1 dictionary

`/dictionary/` (under More) lists Formula 1 terms with search, A–Z and by-topic views. The terms live in `src/dictionary.json` as `{"cats": [[key, name]], "terms": [[term, cat, definition, [also known as]]]}`; the build writes `data/dictionary.json` (loaded only on that page) and prerenders every term into the page HTML. Add a term by adding a row and rebuilding.

## Regulations history

`/history/regulations/` explains every rules era from 1946 to 2026 and the plans after. The text lives in `src/regulations.json` (intro, eras with changes by area, what it meant and who got it right, plus engine, weight and points tables); race wins, titles and champions per era are computed from the results (`yw` in `data/history.json`). Words found in the F1 dictionary are underlined and show their definition on hover or tap.

## Predictor

The free game at `/game/`: every Grand Prix, signed-in players pick the top five and the pole sitter before qualifying starts (P1 5, P2 3, P3 2, P4 1, P5 1, pole 3). Rules are on the page.

- **Sign-in and storage:** Firebase Authentication (Google and email link) and Cloud Firestore, free Spark plan. The browser talks to Firestore directly; `firebase/firestore.rules` decides what it may do (own profile and picks only, picks only before `rounds/{round}.lockAt`, other players' picks only after the lock, leagues by join code, owner renames and removes). `rounds/`, `scores/`, `tables/`, `system/` and `bans/` are written only by the scorer.
- **Scoring:** `scripts/score.py` runs in the update workflow after `update.py`. It keeps `rounds/` in step with `SCHED`, scores a round when its result first appears or changes (the result is `SEASON[round].race`, pole is P1 of `SEASON[round].quali`), and writes `data/game/leaderboard-2026.json` and `data/game/round-<n>.json` (top 100). Display names are re-read every six hours, after a re-score and on manual runs. Without the `FIREBASE_SERVICE_ACCOUNT` secret it does nothing. If scoring fails, nothing is published and the run fails.
- **Replay a round offline:** `python3 scripts/score.py --replay 17 picks.json` (a list of `{uid, name, top5, pole, secondsBeforeLock}`).
- **Setup (once):** create a Firebase project; enable Google and Email link sign-in; add `trackalmanac.com` (and `localhost`) to the authorized domains; create Firestore in production mode; publish the rules (`firebase deploy --only firestore:rules --config firebase/firebase.json`, or paste `firebase/firestore.rules` into the console); paste the web app config into `src/game.json` and rebuild; create a service-account key and save the whole JSON as the repository secret `FIREBASE_SERVICE_ACCOUNT`. Never commit the key.
- **Moderation:** rename a player by editing `pub/{uid}` and `users/{uid}` in the console, or hide one by adding a document `bans/{uid}` (shown as "Player XXXX" from the next table update).
- **Testing:** the rules tests and a scorer test run against the Firebase emulators. Keep them off `main`.
